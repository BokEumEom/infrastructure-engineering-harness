# Reliability Review

1. Resolve service criticality and user journey.
2. Load SLI/SLO and error-budget policy.
3. Gather current evidence for SLI performance and budget consumption.
4. Distinguish acute incident response from chronic reliability debt.
5. Check recent changes and critical dependencies.
6. Classify the reliability state: healthy, at-risk, budget-exhausted, or insufficient-evidence.
7. Recommend the minimum reliability action and state release/change implications.
8. After an incident, capture reusable incident lessons rather than only a timeline.

Required output: reliability state, user impact, evidence IDs, SLO/error-budget interpretation, immediate action, release guidance, follow-up work, and assumptions.
