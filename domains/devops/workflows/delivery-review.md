# Delivery Review

1. Resolve the service, environments, release path, and ownership.
2. Identify the change batch and expected user/operational impact.
3. Load deployment strategy, rollback capability, and quality gates.
4. Gather current delivery evidence: lead time, deployment frequency, failed deployment recovery time, change failure rate, rework rate, and recent release outcomes as available.
5. Find the bottleneck or instability source rather than optimizing a single metric in isolation.
6. Check observability and rollback before approving higher-risk release strategies.
7. Recommend the smallest change to improve both flow and stability.

Required output: delivery state, bottleneck/instability evidence, release risk, missing gates, rollback/recovery assessment, recommendations, and cross-domain reliability implications.
